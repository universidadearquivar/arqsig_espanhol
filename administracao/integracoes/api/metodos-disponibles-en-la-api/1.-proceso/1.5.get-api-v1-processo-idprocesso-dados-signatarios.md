# ✔️ 1.5.GET/api/v1/processo/{idprocesso}/dados-signatarios

El objetivo de este método es permitir que el usuario busque los datos de los firmantes que tienen acción de firmar electrónicamente en un proceso de firma.

En este método, el usuario nos enviará el ID del Proceso, y nosotros retornaremos un JSON completo con la información del proceso y de los firmantes.

## Requisición

<figure><img src="../../../../../.gitbook/assets/image (855).png" alt=""><figcaption></figcaption></figure>

### Detallamiento del Header y Parámetros

**Ref. 01:** “AppKey” es la clave de autorización para autenticarse en la API. Esta clave debe ser válida y estar vinculada a una cuenta ArqSign activa.

**Ref. 02:** “idProceso” - Para obtener el estado del proceso, debe enviarse como parámetro el ID del proceso de firma en la plataforma ArqSign. Este ID la API lo devuelve como retorno de éxito, tras la llamada del método: [**POST​/api​/v1​/processo​/enviar-documento-para-assinar**](https://manual.arquivar.com/manual-arqsign-or-espanhol/administracao/integracoes/api/metodos-disponibles-en-la-api/1.-proceso/1.1.post-api-v2-processo-enviar-documento-para-assinar).

Otra forma de obtener el ID del proceso es a través de la plataforma ArqSign, en la opción “Historial” del documento disponible en las bandejas de [Entrada](../../../../../caixa-postal/caixa-de-entrada.md), [Enviados](../../../../../caixa-postal/enviados.md) y [Excluidos.](../../../../../caixa-postal/excluidos.md)

***

## Validaciones Generales

El sistema debe verificar si la **AppKey** existe, es válida y si la cuenta está con estado activo.

## Retorno validaciones

### Error: 400 - Bad Request

Este error es retornado cuando no es posible interpretar la solicitud y/o el servidor intenta procesarla, pero algún parámetro de la solicitud no es válido; por ejemplo, un recurso mal formateado o un intento de solicitud con datos faltantes. La información sobre la solicitud se proporciona en el cuerpo de la respuesta e incluye un código de error y un mensaje de error.

1. **Ítem obligatorio**: Este mensaje se muestra en singular o plural cuando uno o más ítems obligatorios no han sido enviados en la llamada a la API.
2. **Formato incorrecto**: Este mensaje se muestra en singular o plural cuando uno o más ítems han sido enviados con formato incorrecto.
3. **Ids inexistentes**: Este mensaje se muestra en singular o plural cuando uno o más Ids enviados no existen.
4. **Documento excluido**: Este mensaje será mostrado cuando el documento retornado esté excluido lógicamente.
5. **Algún parámetro está incorrecto o es inexistente**: Este mensaje se muestra cuando la llamada se realiza con algún parámetro escrito incorrectamente o cuando se envía una información que no existe en el método.

### Erro: 401 – Unauthorized

Este error es retornado cuando la clave de autenticación de la API ArqSign está incorrecta o no fue informada correctamente.

### Error: 404 - Not Found

Este error es retornado cuando el recurso solicitado o el endpoint no fue localizado.

### Error: 422 - Unprocessable

Este error es retornado cuando la solicitud fue recibida con éxito, pero contiene parámetros inválidos.

### Error: 500 - Server Error

Este error es retornado cuando:

* Ocurre un error interno en el servidor.
* Ocurre una falla en la plataforma ArqSign.
* Formato del JSON incorrecto.

## **Retorno de éxito**

Status 200 - Success

El sistema retorna los datos de los firmantes del proceso con acción de **Assinar Online**.

<figure><img src="../../../../../.gitbook/assets/image (856).png" alt=""><figcaption></figcaption></figure>

#### **nomeProcesso**

El sistema retorna el nombre del proceso.

#### **status**

El sistema retorna el estado del proceso.

#### **idStatus**

El sistema retorna el id del estado del proceso.

#### **dataConclusao**

El sistema retorna la fecha de conclusión del proceso, si la hubiera.

#### **dataCancelamento**

El sistema retorna la fecha de cancelación del proceso, si la hubiera.

#### **usuarioCancelamento**

El sistema retorna el nombre del usuario que canceló el proceso, si lo hubiera.

#### **dataExpiracao**

El sistema retorna la fecha de expiración del proceso, conforme a la configuración y la fecha de envío/reenvío del documento.

Si **dataReenvio** es igual a null, entonces **dataExpiracao = dataEnvio + ExpiracaoDias**.

Si **dataReenvio** es diferente de null, entonces **dataExpiracao = dataReenvio + ExpiracaoDias**.

#### **signatários**

En esta parte del JSON, el sistema retorna los datos de los firmantes del proceso.

> #### **ordem**
>
> El sistema retorna el orden de firma del firmante.

> #### **idProcessoDestinatario**
>
> El sistema retorna el id del proceso destinatario.

> #### **nome**
>
> El sistema retorna el nombre del firmante.

> #### **idTipoAssinatura**
>
> El sistema retorna el tipo de firma del firmante:
>
> 1 - Firma Electrónica
>
> 3 - Certificado Digital - ICP Brasil
>
> 4 - Certificado Digital - Otros

> #### **idFormaEnvioProcesso**
>
> El sistema retorna la forma de envío del proceso para el firmante:
>
> 1 - E-mail
>
> 2 - Whatsapp

> #### **email**
>
> El sistema retorna el e-mail del firmante al cual fue enviado el proceso.

> #### **telefone**
>
> El sistema retorna el teléfono del firmante al cual fue enviado el proceso.

> #### **papelSignatario**
>
> 1. **pessoaFisica**
>
> El sistema retorna los roles del firmante como persona física, si los hubiera.
>
> 2. **pessoaJuridica**
>
> El sistema retorna los roles del firmante como persona jurídica, si los hubiera.

> #### **tipoAcao**
>
> El sistema retorna el tipo de acción del firmante en el proceso.

> #### **idTipoAcao**
>
> El sistema retorna el id del tipo de acción del firmante en el proceso.

> **idMeioEnvioCodigoSeguranca**
>
> El sistema retorna el id del medio de envío del código de seguridad, si lo hubiera:
>
> 1 - SMS (Solo Brasil)
>
> 2 - Whatsapp
>
> 3 - E-mail
>
> 4 - No enviar

> #### **emailSeguranca**
>
> El sistema retorna el e-mail al cual fue enviado el código de seguridad.

> #### **telefoneSeguranca**
>
> El sistema retorna el teléfono al cual fue enviado el código de seguridad.

> #### **permitirReenviarCodigo**
>
> El sistema retorna la información si se permite reenviar el código de seguridad:
>
> 1 = true o 0 = false

> #### **falhaEnvio**
>
> El sistema retorna la información si hubo falla en el envío del proceso:
>
> 1 = true o 0 = false

> #### **falhaEnvioCodigoSeguranca**
>
> El sistema retorna la información si hubo falla en el envío del código de seguridad:
>
> 1 = true o 0 = false

> #### **assinado**
>
> El sistema retorna la información si el firmante firmó los documentos:
>
> 1 = true o 0 = false

> #### **dataAssinatura**
>
> El sistema retorna la fecha de la firma, si la hubiera.

> #### **assinaturaRecusada**
>
> El sistema retorna la información si la firma fue rechazada o no:
>
> 1 = true o 0 = false

> #### **motivoRecusa**
>
> El sistema retorna el motivo del rechazo, si lo hubiera.

> **anexos**
>
> El sistema retorna los datos de los anexos de los firmantes, si los hubiera.
>
> 1. **id**
>
> El sistema retorna el id del anexo del firmante.
>
> 2. **anexoDocumentoNome**
>
> El sistema retorna el **nombre del firmante + nombre de configuración + nombre del anexo del firmante (con la extensión).**
