# ✔️ 1.1.1.POST/api/v3/processo/enviar-documento-para-assinar

A diferencia de la aplicación ArqSign, que permite agrupar los archivos del proceso, en este servicio cuando se envía el proceso con más de un documento, el servicio lo considera como **una colección de archivos y estos no serán agrupados en un único archivo.** Es decir, no es posible agrupar archivos mediante el servicio de envío de proceso de documentos para firmar.

El usuario debe informar los datos del proceso y de los destinatarios participantes del proceso de firma.

## Autenticaciones y permisos

1. Para autenticarse en la API de ArqSign, el usuario debe informar la **AppKey**, válida, de la cuenta que está enviando los documentos para firma.
2. Solo cuentas con estado **Activo** y con permiso de **Integración ArqSign** pueden enviar procesos vía integración ArqSign.
3. La cuenta debe poseer créditos de **Envios**, **SMS** y/o **WhatsApp**, según la necesidad.
4. En caso de que la cuenta no posea crédito, el sistema devuelve el mensaje:                                    "Saldo de créditos de Envios o WhatsApp o SMS insuficiente"

## Solicitud

**Orientaciones:**

Cuando el campo requerido esté como **“Sí”** = Siempre requerido

Cuando el campo requerido esté como **“No”** = Información opcional

Cuando el campo requerido esté como **“Tal vez”** = En algunos casos será requerido. Para conocer esos casos, consultar la descripción del tema, según el número de referencia de la línea en la tabla.

## Validaciones

### Validaciones específicas

**idResponsavel**

> **Descripción:** Parámetro obligatorio que informa el Id del responsable del proceso. Esta información será considerada como el responsable por el registro y por el proceso, es decir, el “remitente” del proceso. De esta forma, si el usuario informado se autentica en la aplicación, visualizará todos los documentos en el menú “Enviados”.
>
> **Formato:** Guid
>
> **Requerido:&#x20;**<mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- El sistema valida si el id del usuario informado en el parámetro **idResponsable** pertenece a la cuenta en cuestión, permitiendo usuario con estado activo, inactivo o bloqueado.

**nomeProcesso**

> **Descripción:** Parámetro obligatorio que informa el Nombre del proceso.
>
> **Formato:** Varchar(250)
>
> **Requerido:** <mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- El sistema valida la obligatoriedad y tamaño del String.

**idPasta**

> **Descripción:** Parámetro obligatorio que informa el Id de la carpeta del proceso.
>
> **Formato:** Guid
>
> **Requerido:&#x20;**<mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- El sistema verifica si el **idPasta** pertenece a la cuenta de la AppKey informada.\
> idPasta no encontrado.

#### **configuracoesAvancada**

Configuraciones avanzadas para el proceso en relación al tiempo de expiración, aviso de expiración, frecuencia de este aviso, generación del QRCode y obligación de lectura de la colección de archivos del proceso.

Esta parte del JSON no es obligatoria, por lo tanto, si no se envía o se envía como nula, el sistema guarda el proceso con las configuraciones de la cuenta en cuestión.

> **tempoExpiracaoDocumentoDias**
>
> **Descripción:** Parámetro opcional que informa el tiempo en que el proceso estará disponible para firma, hasta que todos los firmantes firmen y el proceso sea concluido.
>
> **Formato:** Smallint, valores entre {1} y {999}
>
> **Requerido:** <mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando la información no se envía o se envía como nula o 0, el sistema considera las configuraciones de la cuenta.

> **avisoAntesExpiracaoDocumentoDias**
>
> **Descripción:** Parámetro opcional que informa el tiempo para que la aplicación inicie el aviso antes de que el documento expire.
>
> **Formato:** Smallint, valores entre {1} y {99}
>
> **Requerido:** <mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando la información no se envía o se envía como nula o 0, se consideran las configuraciones de la cuenta.

> **frequenciaLembretesDias**
>
> **Descripción:** Parámetro opcional que informa el intervalo para avisos de firma.
>
> **Formato:** Smallint, valores entre {1} y {999}
>
> **Requerido:&#x20;**<mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando la información **no se envía o se envía como nula**, el sistema considera las configuraciones de la cuenta.

> **gerarQrCode**
>
> **Descripción:** Parámetro opcional que informa si el QrCode debe generarse o no en el momento de la conclusión del proceso.
>
> **Formato:** Bit, 1 = true o 0 = false
>
> **Requerido:** <mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Si el parámetro **gerarQrCode** no se envía, el sistema considera las configuraciones de generación de qrCode de la cuenta.
>
> Cuando para el proceso en cuestión se esté enviando una colección de archivos (más de un archivo) para firma, el QrCode se genera por archivo. Cada archivo tendrá su QrCode y su página de firma.

> **obrigarLeitura**
>
> **Descripción:** Parámetro opcional que informa la obligatoriedad de lectura de los documentos al firmar.
>
> Cuando el proceso en cuestión posea más de un archivo a firmar, esta información será usada para obligar o no al firmante a hacer clic en cada archivo antes de que el botón “Firmar” se habilite.
>
> Si el proceso en cuestión posee solamente un archivo a firmar, esta información no generará ningún impacto en el proceso de firma.
>
> **Formato:** Bit, 1 = true o 0 = false
>
> **Requerido:** <mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando la información no se envía o se envía como nula, el sistema considera las configuraciones de la cuenta.

> **renovacaoMeses**
>
> **Descripción:** Parámetro opcional que informa el tiempo para definir cuándo el proceso en cuestión necesita ser renovado.
>
> **Formato:** Tinyint
>
> **Requerido:** **No**

**mensagemPadrao**

Mensaje predeterminado que será enviado a todos los destinatarios definidos como firmantes del proceso.

> **titulo**
>
> **Descripción:** Título del mensaje a ser enviado a los firmantes.
>
> **Formato:** Varchar(150)
>
> **Requerido:** <mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Si no se envía el título, el sistema guarda el valor predeterminado conforme a lo siguiente:
>
> Título = ArqSign: \[Nombre del documento informado en el parámetro "nome"]

> **texto**
>
> **Descripción:** Texto del mensaje a ser enviado a los firmantes.
>
> **Formato:** Varchar(max)
>
> **Requerido:&#x20;**<mark style="color:blue;">**No**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Si no se envía el texto, el sistema guarda el valor predeterminado conforme a lo siguiente:
>
> Texto = Usted ha recibido el/los documento(s): \[Nombre del documento informado en el parámetro "nome"] para firma.

**usarOrdemAssinatura**

> **Descripción:** Parámetro obligatorio que informa si se usará o no orden de firma para los firmantes.
>
> **Formato:** Bit, 1 = true o 0 = false
>
> **Requerido:** <mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando el parámetro **usarOrdemAssinatura** sea enviado como **false**, el sistema desconsidera el valor informado en el parámetro “**ordemAssinatura**” de todos los destinatarios con acción de Firmar Online y envía el documento a todos los destinatarios considerando orden 1.
>
> b- Cuando el parámetro **usarOrdemAssinatura** sea enviado como **true**, el sistema valida el parámetro “**ordemAssinatura**” de todos los destinatarios con acción de Firmar Online. Es decir, el parámetro “**ordemAssinatura**” **de los destinatarios** no podrá ser cero o null.

**usarPosicaoAssinaturaAutomatica**

> **Descripción:** Parámetro obligatorio para indicar a la aplicación si el proceso en cuestión tendrá la página de firma al final de cada archivo. En esta página, la aplicación elige automáticamente dónde será posicionada cada firma.
>
> **Formato:** Bit, 1 = true o 0 = false
>
> **Requerido:&#x20;**<mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando el parámetro “**usarPosicaoAssinaturaAutomatica**” sea **true**, la aplicación incluye una página al final de cada archivo con la posición **de la firma de cada** destinatario con acción de Firmar Online, considerando el tipo de persona para cada firmante conforme se describe abajo:
>
> * Para firmantes con el parámetro **assinarComo** = 1 (Persona física), el sistema incluye en la página automática la posición de la firma del tipo **Persona Física** (PF).
> * Para firmantes con el parámetro **assinarComo** = 2 (Persona jurídica), el sistema incluye en la página automática la posición de la firma del tipo **Persona Jurídica** (PJ).
> * Para firmantes con el parámetro **assinarComo** = 3 (Persona física y jurídica), el sistema incluye en la página automática la posición de firma para ambos tipos, una de **Persona Física** (PF) y otra de **Persona Jurídica** (PJ).
>
> Cuando el parámetro “**usarPosicaoAssinaturaAutomatica**” se envía como true, no es necesario enviar los parámetros **definirPosicaoAssinaturaManual** (9.7.7). Pero si en el JSON se envía para algún firmante el parámetro 9.6.7, **esta información será ignorada.**
>
> b- Cuando el parámetro **usarPosicaoAssinaturaAutomatica** se envía como **false**, significa que la posición de las firmas para cada firmante deberá ser informada manualmente para cada archivo del proceso. Siendo obligatorio enviar los datos del parámetro **definirPosicaoAssinaturaManual (9.7.7).**
>
> Importante: En el JSON, todos los destinatarios con acción de firmar online deben tener el posicionamiento de la representación visual de forma automática por la aplicación o manual para todos. No puede haber en el mismo proceso algunos destinatarios con posicionamiento automático y otros sin posicionamiento.

> **ordemAssinatura**
>
> **Descripción:** Parámetro obligatorio que define el orden de firma del firmante en cuestión.
>
> **Formato:** Tinyint
>
> **Requerido:&#x20;**<mark style="color:red;">**Sí, cuando el parámetro usarOrdemDeAssinatura = 1 (true) y cuando para el destinatario en cuestión el idTipoAcao = 1 (FirmarOnline).**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- Cuando el parámetro “**usarOrdemDeAssinatura**” se envíe como **True = 1** y el destinatario en cuestión tenga el parámetro **idTipoAcao = 1** (Firmar Online), entonces esta información es obligatoria.
>
> **Mensaje:** - Cuando el parámetro **usarOrdemDeAssinatura** sea igual a true, es obligatorio definir el orden de firma para los firmantes con acción de Firmar Online.
>
> b- La aplicación no permite el mismo destinatario en la misma orden de firma.
>
> **Mensaje:** Existen destinatarios duplicados en la misma posición de orden de firma. Verifique la lista de destinatarios y configure una orden diferente o elimine los duplicados.

>
> b- Cuando se informan valores, el sistema valida, permitiendo solamente valores iguales a 1, 2 o 3.
>
> **Mensaje:** El parámetro **representacaoVisualAssinatura** permite solamente los valores 1, 2 o 3.

> **nome**
>
> **Descripción:** Parámetro obligatorio que informa el nombre del destinatario que firmará el documento o recibirá una copia.
>
> **Formato:** Varchar (150)
>
> **Requerido:&#x20;**<mark style="color:red;">**Sí**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>

> **alterarNotificacoes**

> 3 - Enviar solamente notificación de finalización
>
> 4 - Enviar notificación de firma y finalización.
>
> Cuando la información **no es enviada o se envía como null**, significa que **se enviarán todas las notificaciones (firma, recordatorio de firma, expiración y finalización)** al destinatario. Es decir, el sistema debe enviar la notificación con el enlace/token del proceso al destinatario en cuestión, según el orden de firma.
>
> Cuando la información **se envía con el valor 1**, significa que el sistema **no** enviará ninguna notificación **(firma, recordatorio de firma, expiración y finalización)** al destinatario en cuestión.
>
> Cuando la información **se envía con el valor 2**, significa que el sistema enviará **solamente** la notificación de firma.
>
> Cuando la información **se envía con el valor 3**, significa que el sistema enviará **solamente** la notificación de finalización de las firmas de los documentos del proceso. Cuando el proceso esté finalizado.
>
> Cuando la información **se envía con el valor 4**, significa que el sistema enviará la notificación de **firma y de finalización** de las firmas de los documentos del proceso.
>
> **Formato:** Tinyint
>
> **Requerido:&#x20;**<mark style="color:blue;">**No**</mark>

> **retornarLinkProcesso - EMBED**
>
> **Descripción:** Parámetro para indicar si el servicio debe retornar el enlace del proceso al destinatario o no.
>
> **Formato:** Bit, 1 = True o 0 = False
>
> **Requerido:** <mark style="color:red;">**Sí, cuando el parámetro alterarNotificacoes sea igual a 1 (No enviar notificaciones) o 3 (Enviar solamente notificación de finalización)**</mark>
>
> <mark style="color:orange;">**Validación:**</mark>
>
> a- El parámetro “**retornarLinkProcesso**” **es obligatorio y debe enviarse con valor 1 - true** cuando el parámetro **alterarNotificacoes** sea igual a **1** **(No enviar notificaciones) o 3 (Enviar solamente notificación de finalización)**
>
> b- Cuando el parámetro “**retornarLinkProcesso**” **sea igual a 1 - true**, el sistema debe generar y retornar el enlace/token de acceso al proceso al destinatario en cuestión, incluso si el proceso tiene orden de firma.
>
> c- Cuando el parámetro “**retornarLinkProcesso**” **no sea enviado**, el sistema debe considerarlo como false.
